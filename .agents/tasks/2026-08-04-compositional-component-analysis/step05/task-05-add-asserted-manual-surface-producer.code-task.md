# Task: Add Asserted Manual Surface Producer

## Description
Implement the transitional `manual`-tagged component path as a structurally distinct asserted surface producer: write its canonical surface from analysis-time-known component data, publish `provenance = "asserted"`, and create no `arcc check` analysis action or report.

## Background
Until `authority: UNKNOWN` is wired in Step 11, the existing `manual` tag stands in for an unanalysed component. Such a component must still publish a surface for dependents without pretending it was checked. The surface file schema is shared with checked components; trust comes from the provider path and absence of a report, not a boolean inside the file. Several current test fixtures use `manual` only to keep an intentionally failing autogenerated `.check` out of `bazel test //...`; those are not unowned components and must be migrated so negative-check coverage continues to use the checked path.

## Technical Requirements
1. Detect `manual` on a component and select an asserted producer path instead of Task 4's checked action. Produce the same `<name>.surface.json` schema with exact packages/symbols, namespace, authority, complete SDK key, producer version, and digest semantics.
2. Use `ctx.actions.write` (or the equivalent analysis-time deterministic write) from data already known to the rule. Do not execute arcc, create a component analysis action, create a report artifact, or claim a checked verdict.
3. Publish `ArccComponentInfo.surface`, `report = None`, and `provenance = "asserted"`. Keep asserted and checked provenance structural; do not add a trusted/provenance flag inside `SurfaceManifest`.
4. Put only the asserted surface in the `arcc` output group for manual components. Default builds remain lazy and existing manifest/layout default outputs remain unchanged.
5. Ensure the asserted writer and checked CLI emitter share canonical field semantics. If Starlark must receive additional key/version/fingerprint metadata from the Step 4 provider seam, extend that seam once and test equality rather than duplicating an independently drifting SDK-key definition.
6. Audit every current `manual` tag. Preserve genuine unowned/manual wrappers on the asserted path, and migrate negative-analysis or fixture-only uses to a checked-component arrangement whose autogenerated failing test remains excluded without misclassifying the component as asserted.
7. Define behavior for explicitly targeting a `.check` of an asserted component: it must fail analysis clearly because no checked report exists, or the macro must omit that test. It must never silently treat an asserted surface as a passing check.
8. Add analysis tests proving asserted output content/provenance, no `ArccAnalysis` action/report, checked/manual structural distinction, and continued negative-fixture coverage.
9. Update public docs, comments, testdata, BUILD metadata, and the migration note that Step 11 replaces this tag-based branch with `authority: UNKNOWN`.

## Dependencies
- Task 2 defines exact surface contents and digest semantics.
- Task 4 defines checked action outputs, provider fields, output group, and target SDK wiring.
- Step 4's stdlib-map provider supplies target configuration identity; Step 11 removes the transitional tag selection.

## Implementation Approach
1. Inventory all `manual` tags and classify each as an asserted wrapper or a test-selection workaround before changing rule behavior.
2. RED: provider/action tests contrasting checked and asserted components, including no report/action and matching schema metadata.
3. GREEN: add the asserted branch and any single-source SDK-key metadata required by the analysis-time writer.
4. Migrate negative fixtures and prove their explicit expect-violation checks still execute checked analysis.
5. Run wildcard/default build tests, focused analysis tests, and the full CI gate.

## Acceptance Criteria

1. **Manual components are structurally asserted**
   - Given a `manual`-tagged component
   - When analyzed
   - Then its provider carries a canonical surface, `report = None`, and `provenance = "asserted"`, with no component analysis action.

2. **Asserted surfaces have complete content**
   - Given manual declared-interface and `PACKAGE_SURFACE` fixtures
   - When their surfaces are built
   - Then they contain the same exact symbols/packages and identity metadata a checked emitter would derive from the same inputs, including namespace, SDK key, format version, producer version, and digest.

3. **Provenance is not self-asserted by the file**
   - Given checked and asserted surfaces with otherwise identical schema content
   - When their providers are inspected
   - Then only provider/report topology distinguishes them; the surface schema contains no checked/asserted bit.

4. **Negative fixtures remain real analyses**
   - Given fixtures previously tagged manual only to suppress an autogenerated failing test
   - When their explicit expect-violation tests run after migration
   - Then they execute the checked analysis action and assert a failing report rather than receiving an asserted surface.

5. **An asserted component cannot masquerade as checked**
   - Given an explicitly requested `.check` for an asserted component
   - When Bazel analyzes it
   - Then it is absent or fails with a clear no-checked-report diagnostic, never passes from the asserted surface.

6. **Default builds remain lazy**
   - Given wildcard/default builds containing checked and asserted components
   - When no `arcc` output group or check is requested
   - Then no checked analysis runs and asserted artifacts are not unnecessarily materialized as default outputs.
